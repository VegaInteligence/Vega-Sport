# Lire et vérifier le registre des exigences

Le registre porte sur 91 critères. Les identifiants A couvrent 38 critères issus des 18 rubriques de l’audit du 16 novembre. Les autres identifiants couvrent les demandes complémentaires, les tickets clos et les calculs nouvellement exposés. Le deuxième CSV recense 26 calculs ou modifications de calcul repérés en comparant les versions.

Les colonnes de production et de branche utilisent quatre états et une catégorie sans objet. `implemented_production` signifie que le critère borné dispose d’une preuve en production. Sur la branche, cette valeur désigne un comportement hérité. `implemented_branch` désigne un comportement ou un livrable vérifié sur la branche. `incomplete` signale un contre-exemple ou une obligation encore dépourvue de vérification suffisante. `missing` signale un mécanisme absent. `not_applicable` s’applique lorsqu’une livraison ou une opération de revue ne peut avoir de statut d’implémentation en production.

Les colonnes suivantes donnent le témoin, les sources, les pièces, le propriétaire et le contrôle encore nécessaire. Dans la capsule, les fichiers listés par `source_paths` sont sous `source/`, les fichiers listés par `evidence_paths` sous `preuves/`. Après extraction, `python3 -B verifier.py` vérifie toutes les références et les empreintes sans connexion.
