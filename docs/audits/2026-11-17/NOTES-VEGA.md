## Player algorithm and remaining gaps

Vega reads finished, positive-minute, team-linked `core.player_match_stats` for ordinary editions whose match date is within the August–July award year. It reads the award-year and following storage partitions. Role is inferred from a team formation slot, a player's other slots in that award, a supported line fallback or keeper data. Unassignable rows leave the model in `assign_roles`. Model blocks admit supported measures with fitted role references. A missing contribution or missing reference yields no grade. The normal score is derived from Vega's role-relative contribution distribution. The SQL views and JS display transform this internal z to `100/(1+10^(-z/4))`. The incoming provider rating was dropped in migration 108. See `backend/vega/power.py:1016`, `:1134`, `:1233`, `:1485`, `:1600`, `:1668`, `:1707`, `backend/sql/107_vega_match_grades.sql:188`, `backend/sql/108_drop_source_rating.sql`, and `dashboard/frontend/src/services/grades.js`.

The stored grade primary key combines the physical edition season, match and player. The independent integrity scan of 2,170,870 grades found zero with missing matches, nonfinished matches, absent source statistics, nonfinite z, incorrect award, team, minutes or foreign run type/award. The persisted grade agrees with the computed index to the method's update tolerance. The proper audit denominator includes short appearances: 321,069 grades persisted but below both UI display thresholds; 1,849,801 met the display rule. A blank UI value can therefore have a valid underlying computation. The transaction updates grades only if values or identity/reference fields change, so a grade can correctly retain the ID of an earlier successful run.

Six ordinary-statistics partitions 2021–2026 contained 2,219,556 confirmed appearances from positive minutes, starting lineups or substitutions. At least 7,860 participants had no statistics row and 1,882 had one without measured minutes. The score grid includes additional goal/shot evidence when available and preserves absent rosters explicitly. A match with a result but no player observations can have unknown participation and unknown score eligibility. A listed substitute who never took the field cannot be treated as eligible.

38,944 inputs lacked an `agg.player_power_matches` row, of which 37,225 were in 2021 and 1,185 in 2025 at this read. The SQL distinguishes a still-unprocessed row that has a directly assignable role from one requiring role history. A missing intermediate with enough information for role assignment is a missing model evaluation. It is not yet proof that a finite grade would result. Replay the affected award with current reference data to distinguish it from insufficient event evidence. In the observed six partitions, zero positive-minute rows were in cup/archive-keyed editions. The hard gate still excludes future complementary cup stats regardless of their merits. A data-driven eligibility rule should accept measured official matches with canonical identity and appropriate role/reference coverage, while retaining the explicit archive-team policy. Do not substitute external player ratings or a numeric zero when no grade is possible.

The worker refreshes all team strengths if an ordinary PitchAPI season is due. Changed primary detail payloads increment `core.matches.updated_at`. Daily model refresh also checks whether a prior award year must be recomputed, and checks published stale method versions. Its prior-year check deliberately requires player stats in the preceding physical season, which can strand a first partially observed award unless match grade availability is handled independently from publishing a season ranking. Source-specific changes to a complementary competition cannot independently make this due-season query fire. None of the score tables has a composite match FK that immediately cascades match deletions for both team Elo and player grades. The rebuild/publish path can clean rows later. Test deletion, rescheduling into another edition and late historical inputs through normal worker entry points. See `backend/vega/worker.py:93`, `:485`, `:512`, `backend/vega/models.py:780`, `backend/vega/power.py:1464`, and `backend/vega/store.py:794`.
