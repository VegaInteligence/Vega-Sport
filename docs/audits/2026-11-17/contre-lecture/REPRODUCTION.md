## Essais PostgreSQL sur données construites

Le contrôle portable ci-dessus vérifie les résultats des deux essais PostgreSQL effectués par la piste 5. Pour réexécuter les scénarios, utiliser Python 3.14 avec les dépendances du worker, un checkout du commit de production figurant ci-dessus et un PostgreSQL 18 local. Le premier essai utilise le conteneur de test Colima `vega-vi27-audit-ci-pg18` déjà disponible sur `127.0.0.1:55439`. Le second crée et arrête son propre cluster éphémère avec authentification locale. La copie de travail préserve les reçus publiés.

```sh
SCIENCE_DIR="$PWD/docs/audits/2026-11-17/contre-lecture"
SCIENCE_TEST=$(mktemp -d)
cp -R "$SCIENCE_DIR/joueurs" "$SCIENCE_TEST/joueurs"
python3 "$SCIENCE_TEST/joueurs/first-award/run.py" "$VEGA_DEPLOYED_CHECKOUT"
python3 "$SCIENCE_TEST/joueurs/psl-lineage/double-side.py" --repo "$VEGA_DEPLOYED_CHECKOUT" --pg-bin "$VEGA_PG18_BIN" --out "$SCIENCE_TEST/joueurs/psl-lineage/essai-equipe-tierce"
```

Pour la première fenêtre, la passe ordinaire donne 50 notes sur 100 et la simulation du changement de méthode donne 100 notes réparties entre deux années. Dans le second essai, les deux tentatives renvoient `23505`, les lignes précédentes gardent leurs empreintes et la correction du côté permet la publication suivante. Le test déclenche les tentatives explicitement. Il n’établit pas que la PSL a connu ce défaut.
